cryptship

Encrypted, license-gated code in container images

Docker images ship your source in the clear: anyone can docker save and read it. cryptship ships the app encrypted, with a thin loader that decrypts and runs it only when a valid license is present. One tool, one license format, three deployment modes.

GitHub → v0.1.0 release How-to guide

How it works

Build time on your side, run time on the customer’s.

Build time · vendor

Your app
Source or compiled build output
↓
cryptship pack
Random content key; AES-256-GCM into payload.enc
↓
cryptship issue
Ed25519-signed license that wraps the content key
↓
Container image
Loader + payload.enc + license + public key

Run time · customer

Loader starts
Verifies the license signature, expiry and revocation
↓
Key provider
offline · online license server · attested hardware
↓
Decrypt to tmpfs
Wrong license or machine means the AEAD tag fails
↓
exec your app
Runs with the license ID and customer as a watermark

The key idea

There is no “is the license valid?” check to patch out. The decryption key is derived from the license itself.

no "is valid?" boolean to patch 
# the key is derived from the license, so a valid license and a successful decrypt are the same event
content_key = unwrap(license.wrapped_key, KEK = derive(machine_fingerprint, license_id))
plaintext   = aead_open(payload.enc, content_key)   # wrong key => AEAD tag fails

Deployment modes

Hardening

🧱
Compile before sealing
pack --transform-cmd runs your toolchain first, so a memory dump yields bytecode, not source
🛡️
Runtime hardening
Non-dumpable loader, seccomp profile, non-root, dropped capabilities, read-only root and tmpfs
🔖
Per-license watermark
Each instance carries its license ID and customer, so a leak traces back to its licensee
🔁
Key rotation and revocation
Signing-key ring, and open, closed or grace revocation policies
Honest threat model
Code that runs on hardware the customer controls can never be fully extraction-proof. cryptship raises the bar: it makes casual copying impossible and serious reverse engineering cost more than a license. Against root on the host, only the confidential-compute (attested) path, or keeping critical logic server-side, prevents extraction.
